# draft-valuation

Arguments: `<TICKER> [--redraft]`

## Procedure

Read the [root instructions](../../../AGENTS.md), [reader rules](../../../docs/research.md#section-3), [review guide](../../../docs/review.md), [model specification](references/model-spec.md), [assumptions specification](references/assumptions-spec.md), [drafting contract](references/workflow-contracts.md#drafting), and [analyst playbook](references/analyst-playbook.md). Use the [sourcing guide](../../../docs/sources.md) and `companies/<TICKER>/source-guide.md` when gathering evidence. The playbook routes topical references by decision. For the required draft app check, read [the exact check and review-only loading instructions](../../../tools/valuation/APP_GUIDE.md#required-draft-app-check). Give the analyst and reviewer these applicable requirements; historical lessons are read only when relevant.

The [teaching library](../../../tools/valuation/damodaran-notes/README.md) indexes cached primary text and provenance. The analyst applies the guides to the evidence note and input cells; the reviewer reads [review-checklist.md](references/review-checklist.md) and checks those applications against the original passages. Historical examples are optional and never current benchmarks. Apply the [case definitions](references/uncertainty-and-bias.md#apply-to-this-repository), [investment-payoff check](references/business-drivers.md#investment-payoff-check), and cross-company risk comparison; narrative and numbers must respond to the evidence together. This skill sequences the requirements; it does not add approval gates.

1. **Resolve prerequisites and target.** Follow [§18.7](references/workflow-contracts.md#drafting) step 1. Research prerequisites may be routed only when covered by the request. Existing assumptions require `--redraft` or an explicit redraft request before replacement. For an authorized redraft, copy the existing files to a unique history directory, retain the active files, and prepare a separate candidate. Use the selected `<ASSUMPTIONS>` YAML path for every command below; never accidentally validate the old active file. Hand any owner-edited cells and their values to the analyst for the required comparison.

2. **Resolve the period.** Read the quarter label from `outlook.md` and the cutoff from its source manifest. Apply [§12.5](../../../docs/sources.md#section-12-5). Prepare `sources/<QLABEL>/notes-valuation-evidence.md` under [§18.4](references/assumptions-spec.md#section-18-4) rule 16 before drafting: reuse eligible sources across the library, then fetch targeted pre-cutoff peer, market and operating evidence for material gaps. Apply [model selection](references/model-selection.md), [accounting](references/accounting-and-reinvestment.md) and [uncertainty](references/uncertainty-and-bias.md) to the evidence note: model fit, supported accounting treatment, benchmark selection, major risks and unresolved gaps. Read existing `valuation/lessons.md` and eligible forecast assessments before setting a new path on an authorized redraft. Give the analyst the evidence note and permitted cache, including prior periods needed for trailing-twelve-month calculations. These targeted fetches are part of drafting; research-report rebuilds remain outside this skill.

3. **Draft with one analyst subagent.** Give it the shared boundaries, reader rules, model and assumptions specifications, the playbook, target path, fiscal calendar, cutoff, `business.md`, `outlook.md`, `scorecard.md` if present, and permitted sources. It writes provisional stories, revises them with the operating builds and follows all sixteen rules in [§18.4](references/assumptions-spec.md#section-18-4), using [business-drivers.md](references/business-drivers.md) for the story-to-numbers table, segment build, lagged reinvestment history, margin bridge and terminal economics. Record which lessons changed which inputs and explain any rejected lessons. Each material input must distinguish observed facts, analyst judgments, arithmetic, a defensible range and a development that would change the choice (rule 15). Benchmark the mature business under rule 16. Numbers it cannot defend stay null. It fetches nothing; the runner resolves specific evidence requests and fills market-derived cells. Uncertain future estimates can be labelled supported judgments; missing historical facts or an unsupported material model cannot be disguised as assumptions. Every reason is one to three plain sentences; working numbers belong in `detail`, not YAML comments.

4. **Fill, validate and check in the app.** Follow [§18.7](references/workflow-contracts.md#drafting) step 3: use cached industry data and the direct price-fetch command, without computing a valuation merely to obtain the price. Record sources and dates. Run `uv run value <ASSUMPTIONS> --validate` and handle errors, stopped cases, and unavailable evidence under [§13](../../../docs/review.md#section-13). Render `assumptions.md` beside the candidate with `uv run value <ASSUMPTIONS> --render-assumptions`, including for a blocked draft; regenerate after edits. After the narrative and inputs are built, perform [§18.10](../../../tools/valuation/APP_GUIDE.md#section-18-10)'s required draft app check on that exact target in review-only mode. The narratives and review controls must render and work even when missing inputs prevent calculation; a validator or Markdown render alone is insufficient. Record the outcome in `review/<QLABEL>-valuation-app-check.md`.

5. **Independent review.** Give a reviewer the target YAML, playbook, shared boundaries, applicable specifications and review guide, and the same permitted sources. It performs [§18.7](references/workflow-contracts.md#drafting) step 4 and the [review checklist](references/review-checklist.md), independently reconstructs material evidence-to-input bridges, and verifies mature-peer comparability. A terminal premium chosen to clear a diagnostic threshold must be revised; absent material benchmark or substitute evidence is BLOCKED, not PASS with a caveat. It writes `review/<QLABEL>-valuation-draft-review.md`. Use `uv run value <ASSUMPTIONS> --diagnostics-only` for cash flows, returns, and transition checks without displaying valuation results. The reviewer may fix wording and source tags; numbers and judgments go back to the analyst. Follow [§13](../../../docs/review.md#section-13)'s two-pass limit, N/A/BLOCKED handling, and completion rules.

6. **Promote and commit only after PASS.** Follow [§18.7](references/workflow-contracts.md#drafting) step 5: check the active files against the archived snapshot before promoting a redraft; preserve both versions and ask about reconciliation if the owner edited them meanwhile. Regenerate active `assumptions.md`. Keep any existing `valuation.md` as the prior computation and disclose that it predates the new assumptions. Freeze a separate analyst-proposal record using [forecasts-and-learning.md](references/forecasts-and-learning.md) and [§18.12](references/forecasts-and-learning.md#section-18-12): exact inputs, creation time, model windows, operating targets and definitions, without valuation results. Commit the passing draft and record as `value(<TICKER>): draft assumptions as of <QLABEL>` per [§16](../../../AGENTS.md#section-16). A failed candidate stays separate and is not committed as a completed draft.

7. **Verify the final app check and present for owner review.** Confirm the [§18.10](../../../tools/valuation/APP_GUIDE.md#section-18-10) check covers the final narrative/input hash and app version; repeat it after any changes, including on BLOCKED/REVISE drafts. Report the four stories in one line each, five inputs worth attention, evidence gaps, reviewer verdict, owner-value differences, readable draft path, and app-check outcome/record. A prior app audit does not replace this check of the new draft. After PASS, the next step is to read `assumptions.md`, then choose computation in the app (`uv run --extra app valuation-app`) or request `/compute-valuation <TICKER>`. For BLOCKED/REVISE, name the remaining work instead of directing the owner to compute unsupported inputs; distinguish financial-review gaps from rendering failures.

The [draft-review boundary](references/workflow-contracts.md#draft-review-boundary) applies: internal `--diagnostics-only` computation is authorized; ordinary `--dry-run`, full result JSON, valuation-result disclosure, and writing `valuation.md` are not part of this skill. Present the draft first and wait for the owner's subsequent compute request or app choice. Do not ask for another confirmation after that request.
